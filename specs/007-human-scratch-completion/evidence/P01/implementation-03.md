## Two charter factual errors found and root-approved corrections

The original dispatch prescribed `next@16.2.12` and a `package.json` `pnpm.overrides` block. Both
were factually wrong in this environment; I stopped before writing outside allowed paths and root
independently verified and approved the corrections (HANDOFF.md "CHARTER CORRECTION"):

1. **`next@16.2.12` is age-suppressed by the repo's `safe-chain` policy.** 16.2.12 exists in the
   registry (dist-tag `latest`, published 2026-07-25) but is only 3 days old (today 2026-07-28) and
   `safe-chain` suppresses it during resolution ("No matching version found for next@16.2.12 ... The
   latest release of next is 16.2.11" + "Some package versions were suppressed ... due to minimum
   package age"). Installing it would require `--safe-chain-skip-minimum-package-age`, i.e.
   violating the supply-chain policy the frozen HS-002 text depends on. The latest
   **safe-chain-supported** release is **`16.2.11`** (published 2026-07-21, 7 days old), which is
   the patched version for all 9 next advisories (`patched >=16.2.11`). Used 16.2.11.

2. **pnpm 11.13.1 ignores `package.json` `pnpm.overrides`.** Every `pnpm install` printed
   `[WARN] The "pnpm" field in package.json is no longer read by pnpm ... "pnpm.overrides"` ignored.
   The real mechanism is the existing `overrides:` block in `pnpm-workspace.yaml`. Root expanded
   allowed-writes to include `pnpm-workspace.yaml`; sharp override added there.
