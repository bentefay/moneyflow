### 5A. BLOCKING finding — `identity.spec.ts:282` "validate BIP39 words with visual feedback"

- **Failure (run #1):** `expect(validClasses).not.toBe(invalidClasses)` at `identity.spec.ts:365`. A
  valid BIP39 word (`abandon`) and a non-word (`invalidword123`) were typed into
  `seed-word-input-0`; the test read the input's `class` after each and asserted they differ. The
  captured class for the invalid read still contained `border-input` and **lacked**
  `border-destructive` — i.e. the validity styling had not yet flipped when the class was read, so
  both reads were equal.
- **Mechanism (product is correct):** `src/components/features/identity/SeedPhraseInput.tsx` derives
  `wordValidation` via a synchronous `useMemo` on `words` state (`:120`) and applies
  `border-destructive focus-visible:ring-destructive` when `showError` (`:338`,`:343`). The test's
  own comment (`:349-353`) documents the exact race: a fill landing before React hydration is
  dropped, `onChange` never fires, `words` never updates, and the class stays neutral. The added
  guards (`toBeEditable` + `toHaveValue`) are **insufficient** — a DOM value can be present
  pre-hydration while the memo-driven className has not committed.
- **Characterization (isolation):** targeted reruns are green —
  `identity.spec.ts:282 --repeat-each=15 --workers=1` → **15/15 pass**;
  `--repeat-each=24 --workers=4` → **24/24 pass**. The flake manifests only under FULL 163-test
  parallel load — the same profile as the tracked `import.spec.ts:301` (~1-in-489) vault/hydration
  race, but a **different, undocumented test**.
- **Classification:** a pre-existing hydration-timing E2E flake; product behavior (BIP39 visual
  feedback) is correct. It is NOT a data/security/logic defect. However it is **undocumented** (no Q
  proposal, not among the two accepted residuals) and it **broke the final-audit full-suite run**.
- **Why blocking:** GOAL DoD requires the complete E2E suite to pass clean under the final audit
  with no accepted unexplained flake; P21 contract makes a NEW flake blocking. Both are violated.
- **Recommended routing (root):** test-only hydration-wait hardening of this step (mirror the prior
  P20B fixes `3a241f8`/`9de7285` that added hydration waits before other fills) — wait for the
  validity class to change before reading it, rather than relying on `toHaveValue`. No product
  change is indicated. Owning area: identity/onboarding E2E (P05/onboarding lineage). Also warrants
  a tracked Q proposal so the residual is disclosed rather than silent.
