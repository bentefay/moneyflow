## Recursive private-shadow boundary

- Top-level direct-location and ID-only query matches now require `isPublicTransaction`, and neither
  query traverses nested children of a private parent. Existing mutation traversal already applies
  the same parent guard before top-level or nested update, move, delete and import-delete work.
- The public React `useTransaction` hook now applies that guard before both its top-level identity
  check and nested traversal. It therefore rejects malformed, legacy and in-progress private parents
  rather than relying only on the shape generated by current maintenance. The implementation keeps
  returning stable objects already held in provider state; an attempted delegation through the
  materializing ID query was rejected during development because it made nested selector snapshots
  unstable.
- Every newly attached nested shadow begins with the reserved maintenance identity, not its public
  transaction ID. Its public ID is installed only in the same bounded step that finishes that
  child's tags and allocations. Therefore raw selectors that scan nested IDs cannot match an
  incomplete child during any generated phase.
- The oversized attached-shadow regression observes every maintenance commit across 64 nested
  children. Reserved-ID children always resolve through both public query exports to the complete
  source; any nested child that has its public ID already has its complete tag and allocation
  payload. The test still proves more than 300 bounded applies, no non-empty attached map, unique
  public IDs, `system:gc` origins and at most 24 observed map/list operations per commit.
- Stale shadow scalar values are revalidated against the exact source container. An invalid shadow
  is deleted in one bounded list operation instead of being allowed to advance or reveal.

## Conservative mixed-batch classification and crash safety

- Every maintenance commit carries the private Loro change message
  `__moneyflow_gc_commit_v1__`. No public vault value stores that discriminator.
- Imported domain events are queued before any plan can advance. A persistent cursor over Loro ID
  spans examines at most the frame item/time budget and classifies individual changes by commit
  message. A single non-maintenance change clears imported maintenance acceptance, invalidates
  process-local shadow trust and schedules a fresh proof pass before reveal.
- Maintenance-only imports may trust and finish the exact source-CID shadow without producing a
  local echo. Mixed maintenance/user imports, user-first imports and dependency-delayed imports all
  retain the user edit and finish with no private shadow.
- Shadow authority is process-local. A crash or reload loses trust, so a persisted partial shadow
  is discarded with one bounded list deletion and rebuilt from its exact source; it is never
  blindly resumed. There is no persistent epoch/source marker to leak or require an unbounded
  cleanup scan.
