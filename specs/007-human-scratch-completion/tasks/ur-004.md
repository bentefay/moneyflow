# UR-004 — Default currency inferred from time zone

- **Status:** queued
- **Source:** `specs/009-user-reported-refinements/spec.md` lines 76-98 (frozen, markerless)
- **Owning package:** P25
- **Completion:** ledger-only, after implementation and DISTINCT independent review

## Required behaviour (rule from the frozen text)

Time zone is the PRIMARY signal for the inferred default currency. Locale-derived inference remains
a FALLBACK for when the time zone yields no country (e.g. `UTC` in containers/VMs). A final fallback
currency applies when neither yields a supported currency. The time-zone-to-country mapping uses an
established, maintained library — NOT a hand-written table; the existing country-to-currency map may
be reused. The inferred value is only a default: it is shown in the vault creation flow and the user
can change it before and after creation, never silently locked in.

## Orientation (verify yourself)

`src/lib/domain/detect-currency.ts` today resolves `navigator.languages[0]` -> BCP 47 region subtag
-> `REGION_TO_CURRENCY` (`:170-260`, ~70 countries), falling back to USD. Its header comment at
`:4-6` asserts locale is more reliable than time zone; that rationale is empirically WRONG and is
superseded by this requirement — update or remove the comment so it does not contradict the shipped
behaviour. Measured counterexample from the reporting user: `LANG=en_US.UTF-8` (hence
`navigator.language` `en-US`) with time zone `Australia/Brisbane` — locale yields USD, time zone
yields the correct AUD. `en-US` is the default locale on most Linux installs and container images,
so locale-derived region silently collapses to `US` for many non-US users.

Per CLAUDE.md, use an established library for the IANA-zone -> ISO-3166 mapping; a custom table is a
bug waiting to happen. Vet any new dependency for maintenance and licence, and record the choice in
evidence. Keep the module pure and side-effect free; retain safe behaviour when `Intl` or the time
zone is unavailable.

## Tests

Unit/table-driven coverage: time zone wins over a conflicting locale (Brisbane + en-US -> AUD);
`UTC` falls back to locale; neither resolving falls back to the default currency; unsupported
currency codes fall back. E2E asserting the vault creation flow shows the inferred default and that
the user can change it.
