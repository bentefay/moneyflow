## The reported defect, and root's read of the code

The principal added a tag and changed a description on an imported transaction and NO controls
appeared, so no rule could be created or applied to other transactions.

Root's read, to be verified independently rather than trusted:

- `computeFieldRuleRobotState` (`src/components/features/transactions/field-rule-robot-state.ts`)
  returns `{kind: "none"}` whenever `selectWinningRule` finds no existing rule. `page.tsx:486-505`
  renders `TransactionRuleRobot` only when that state is NOT `none`. This is CORRECT for the robot:
  the frozen text says the robot surfaces a rule that already exists.
- The frozen text ALSO requires a SECOND, DISTINCT surface: `human-scratch.md:249-252` says that
  when you apply a description alias "where the description text doesn't already match a rule, some
  controls appear" — the four-choice select, tick button, "only if $x" and "only this account".
  `:289-292` then says description, tags and person percentage rules "work similarly", with an extra
  "add tags" / "set tags" select for tags.
- Root found NO component implementing those creation controls: a repo-wide search for a proposal or
  rule-creation surface under `src/components/features/transactions/` returned nothing, and
  `InlineEditableTags.tsx` contains no robot or proposal wiring at all.

So the likely gap is that the DRIFT/existing-rule surface shipped while the CREATION surface did
not, for every field. Verify this yourself before fixing; do not assume root's read is complete.

## Root's second pass — the gap is now traced, not just suspected

Root's earlier read said the creation controls appeared absent. A closer look confirms it and
locates the boundary precisely. **Verify all of this yourself**; several of root's readings have
been corrected by workers in this goal, two of them in the immediately preceding package.

- **No creation surface exists anywhere.** `grep -rln 'RuleProposal|proposeRule|createRuleFrom'`
  over `src` returns NOTHING.
- **The existing-rule surface is well developed**, which is what makes the gap easy to miss:
  `TransactionRuleRobot.tsx`, `TransactionRulePopup.tsx`, `field-rule-robot-state.ts`,
  `description-rule-state.ts` and `use-transaction-rule-workflow.ts` all exist and are wired.
- **The workflow hook has no create path, and says so.** `use-transaction-rule-workflow.ts` exposes
  `save(ruleId)`, `remove(ruleId)`, `applyAll()`, `applyNew()`, `applyThis()`, `setDraft`,
  `resetDraft` — every mutation is keyed to an EXISTING `ruleId`. Its comment at `:212` reads
  _"Editing an existing rule from a matching transaction: UPDATE, never create."_ That is a
  deliberate design boundary, not an oversight, and it is exactly the boundary the frozen text
  requires crossing.
- **The tags cell has no rule wiring at all**: `grep -c 'rule|Rule'` over `InlineEditableTags.tsx`
  returns **0**. So the principal's report — added a tag, saw no controls — is explained without
  appeal to timing or state.

**What this means for the package.** The frozen text at `human-scratch.md:249-252` requires controls
when the field "doesn't already match a rule", and `:289-292` extends the same behaviour to tags and
person percentage with an extra add/set select for tags. The shipped code implements the DRIFT half
of `:275-288` — a robot for a rule that already exists, red when the field has drifted, opening the
automations-page editor — and does not implement the CREATION half at all.

So this is additive work against a codebase whose existing half is sound, not a repair of something
broken. Reuse `use-transaction-rule-workflow` and the automations-page editor as the frozen text
requires rather than building a parallel surface, and extend the hook with a create path rather than
working around its `ruleId` keying.

**Do not let the clause-by-clause audit become a rewrite.** The audit table required above is the
first deliverable precisely so the conforming clauses are recorded as conforming. A clause the
shipped code already satisfies should be marked PASS with its citation, not re-implemented.
