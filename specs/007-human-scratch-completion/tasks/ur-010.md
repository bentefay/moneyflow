# UR-010 — Shift-click extends selection and deselection symmetrically

- **Status:** queued
- **Source:** `specs/012-transaction-selection/spec.md` lines 11-29 (frozen, markerless)
- **Owning package:** P31

## Root's read, to VERIFY rather than trust

`toggleRow` in `src/components/features/transactions/hooks/useTableSelection.ts:106-133` already
implements a shift range, but only ever ADDS:

```
if (shiftKey && lastSelectedId !== null) {
    const startIdx = filteredIds.indexOf(lastSelectedId);
    const endIdx = filteredIds.indexOf(id);
    if (startIdx !== -1 && endIdx !== -1) {
        const [from, to] = startIdx < endIdx ? [startIdx, endIdx] : [endIdx, startIdx];
        for (let i = from; i <= to; i++) newIds.add(filteredIds[i]);   // <- always add
    }
}
```

So the principal's report is precise: the select direction works, the deselect direction does not.
`lastSelectedId` records WHICH row was last acted on but not WHAT was done to it, so the range has
no direction to apply. That missing piece is the requirement.

The pointer entry point is `CheckboxCell.tsx:48` (`event.shiftKey && onShiftClick`); keyboard range
handling lives in `hooks/useKeyboardNavigation.ts:221` and `:258` and must follow the same rule.

## Required behaviour

Rule from the frozen text. In summary: the range applies the SAME outcome as the anchor received — a
range begun by selecting selects, one begun by deselecting deselects; the range spans the rows
between anchor and clicked row in the table's current presented order under active filters and sort,
inclusive of both ends; rows outside the range keep their state; the clicked row becomes the new
anchor; with no anchor the click is an ordinary toggle.

Keep the hook pure and its data immutable — it already builds a new `Set` rather than mutating.

## Tests

Table-driven unit coverage over `useTableSelection`: select-range, deselect-range, range crossing in
both directions, anchor reset, no-anchor fallback, rows outside the range untouched, and a range
whose endpoints are reversed. E2E asserting the reported gesture: select rows, untick one,
shift-click a ticked row above or below, expect the rows between to be unticked and the rest
unchanged.
