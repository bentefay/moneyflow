# UR-001 — Add transaction focuses the description instead of selecting the row

- **Status:** queued
- **Source:** `specs/009-user-reported-refinements/spec.md` lines 12-33 (frozen, markerless)
- **Owning package:** P22
- **Completion:** ledger-only, after implementation and DISTINCT independent review

## Required behaviour (rule from the frozen text, not from this summary)

Creating a transaction must not change the selection set, and must focus the new row's description
input once the row is rendered. Existing discoverability behaviour is retained: filters reset, the
page extends to include the new row, and the row is scrolled into view. The focus intent is consumed
exactly once then cleared. The grid is virtualized, so focus must happen only when the row is
actually mounted and must survive the scroll-into-view.

## Orientation (verify yourself)

`handleAddTransaction` at `src/app/(app)/transactions/page.tsx:538-585` currently ends with
`setSelectedIds(new Set([transactionId]))` at `:584` — remove that. Discoverability already comes
from `setFilters(createEmptyFilters())` (`:542`), the `displayCount` bump (`:571-579`) and
`setTransactionIdToReveal` (`:580`), which drives the reveal effect at `:303-321`. Prefer extending
that existing consume-once reveal channel over adding a parallel mechanism; keep the consume-once
discipline described in the comment at `:296-297`. Ref-then-focus precedent exists at
`TransactionRow.tsx:254`, `PersonAllocationCell.tsx:104`, `InlineEditableTags.tsx:134`,
`BulkEditToolbar.tsx:107-110`.
