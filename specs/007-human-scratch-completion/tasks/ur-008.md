# UR-008 — CSV import parity with OFX, and honest import counts

- **Status:** queued
- **Source:** `specs/010-user-reported-refinements-2/spec.md` lines 56-86 (frozen, markerless)
- **Owning package:** P29

CSV and OFX exports of the same activity must import identically, and the summary must describe its
counts truthfully.

## Confirmed root cause for the reported errors

`parseAmount` in `src/lib/import/csv.ts:165-190` strips currency symbols, handles accounting
parentheses and handles a leading `-`, but has NO branch for a leading `+`, so `+69.00` fails
magnitude validation and the row is reported as an error. The principal's CSV contains EXACTLY 15
such rows, which matches the 15 errors reported. Fix the parser to accept an explicit plus sign.

Also verified in that file: 10 rows carry a quoted description containing a comma
(`"PAYMENT RECEIVED, THANK YOU"`), so quoted-delimiter handling must keep them as one field.

## Other required behaviour

- `collapseWhitespace` defaults to TRUE for new imports of every supported type. It is currently
  `false` at `src/lib/import/types.ts:154`.
- Column detection runs AUTOMATICALLY when a delimited file loads, and works with NO header row.
- Detection is value-driven: parses-as-date is the date column, parses-as-amount once symbols and
  signs are handled is the amount column, remaining text is the description.
- Date-format detection works from values alone, including day-first `dd/MM/yyyy`, with no header.
- The summary must separate rows excluded as OLD, rows excluded as DUPLICATES, and rows that are
  BOTH, so no count is ambiguous about why a row was excluded or whether it will be imported. The
  principal reported `561 old, 46 duplicates, 15 errors` as confusing on exactly this point.

## Tests

Add fixtures derived from the principal's files. Do NOT commit real financial data: generate
synthetic fixtures with the same STRUCTURE — no header, `dd/MM/yyyy`, quoted fields, at least one
leading-plus amount, at least one quoted description containing a comma. Assert CSV and OFX of the
same synthetic data import to identical transactions with ZERO errors, that auto-detection runs
unprompted and maps all columns, that the date format is detected, and that old/duplicate/both
counts are reported distinctly.
